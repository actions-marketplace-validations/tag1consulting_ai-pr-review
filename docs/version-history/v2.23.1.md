# v2.23.1

## Fixed

- **Bitbucket finding numbers are kept across runs (#1065).** Bitbucket keeps one summary comment and rewrites it on every run. The hidden id-map marker used to hold only the findings of the current run. An incremental run that did not report a finding again dropped its `F<n>`, so a waiting verdict command got "F<n> was not found in the current review". A run with no findings restarted the numbering at F1, so a waiting command could apply to a different finding. The marker now keeps earlier entries within a size budget (4,000 bytes of JSON, about 5.4 KB in the comment). The lowest numbers go first and the highest number always stays. A finding that returns after a run without it keeps its number and no longer gets the "new" badge. A WARNING in the job log shows when earlier entries were dropped. GitHub and GitLab are unchanged. See [Bitbucket setup](../bitbucket-setup).

## Changed

- **Container image tool updates (#1061, #1062, #1063).** The image uses ruff 0.17.1, golangci-lint 2.15.0, and a newer digest of the Ubuntu 26.04 base image.
